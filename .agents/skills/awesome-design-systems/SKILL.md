# Awesome Design Systems

> A design system is a collection of documentation on principles and best practices, that helps guide a team to build digital products. They are often embodied in UI libraries and pattern libraries, but can extend to include guides on other areas such as 'Voice and Tone'.

Source: [alexpate/awesome-design-systems](https://github.com/alexpate/awesome-design-systems) — 25,000+ GitHub stars.

---

## How to Use This Skill

When the user asks about design systems, follow this workflow:

1. **Understand the need** — Are they choosing a design system? Building one? Looking for inspiration?
2. **Recommend from the reference** — Use the curated list below to suggest relevant design systems
3. **Compare features** — Use the tags (Components, Voice & Tone, Designers Kit, Source Code) to help filter
4. **Provide links** — Always link to the design system's website and source code when available

## How to Evaluate a Design System

When helping users choose a design system, consider:

1. **Framework compatibility** — React, Vue, Angular, Web Components, framework-agnostic?
2. **Component coverage** — Does it have the components needed?
3. **Accessibility (a11y)** — WCAG compliance, ARIA support
4. **Customization** — Theming, design tokens, CSS variables
5. **Documentation quality** — Examples, guidelines, API docs
6. **Community & maintenance** — Stars, contributors, release frequency
7. **Bundle size** — Tree-shaking support, individual component imports
8. **Design file availability** — Figma, Sketch, Adobe XD files for designers
9. **Voice & Tone guidelines** — Content strategy included?
10. **Enterprise readiness** — SSR support, TypeScript, testing utilities
